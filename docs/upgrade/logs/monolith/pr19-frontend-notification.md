# PR19 聚合消息中心 — 前端实施记录

## 背景

在 PR19 的后端延时队列（Delay Queue）与死信弹射架构（DLX）落地后，系统能够在预约到店前 1 小时自动生成“待办提醒”站内信。为了承接这一能力，并且兼顾原有 PR18 的库存告警能力，前端必须对原有的单个小铃铛进行升级。

## 重构内容

### 1. 站内信 API 客户端 (`siteMessage.ts`)
- 按照契约接入了后端的 REST API，包含 `getUnreadCount`、`list`、`markAsRead` 和 `markAllAsRead`。
- 通过 TS 接口约束，解决了 `Untyped function calls` 的编译报错。

### 2. 多状态双 Tab 消息中心 (`AppLayout.vue`)
- 移除了原有的纯库存告警展示。
- 采用 `<el-tabs>` 构建了「待办提醒」与「库存预警」双面板。
- 采用 `Promise.all` 实现了多个微型 API 的并发拉取，降低了弹出框白屏时间。

### 3. 智能焦点与状态同步修复
- **焦点自动切换**：打开消息中心时，如果待办列表为空但库存告警有数字，则会自动跳转到库存预警面板，避免展示空白。
- **幽灵角标修复**：在跨页面补充库存或点击已知悉时，不仅会重新拉取列表，还会从接口获取最新的 `total` 值强制同步回顶部的全局数字角标中，彻底消灭了“列表为空但角标还有数字”的状态失联 Bug。
- **后端联动修正**：修复了由于 `SiteMessageService.pageMessages` 未过滤 `isRead = 0` 导致前端已读消息无法消除的深层隐患。

## 最终效果
- 完美的深浅色模式适配。
- 文本超长时的 `-webkit-line-clamp: 2` 省略号截断保护。
- 无任何 Vite 与 vue-tsc 构建报错，顺利完结。
