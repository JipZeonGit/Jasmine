# PR4 接口规范化说明

## 本轮目标

这一轮的目标不是重写整套业务接口，而是先把用户登录态这条主链路规范下来，主要包括：

- 登录接口入参改为明确的 DTO
- 获取当前用户信息不再接收 `token` 查询参数
- 前端请求头统一切换为 `Authorization: Bearer <token>`
- 后端移除对 `X-Token` 和 `token` 查询参数的业务兜底
- 用户列表返回从 `Map` 收口为明确的表格数据结构
- 补充全局参数校验异常处理

## 主要改动

### 1. 登录与当前用户接口规范化

后端新增了 `LoginDTO`、`LoginVO`、`UserInfoVO`，把原来基于 `User` 实体和 `Map<String, Object>` 的登录/用户信息接口改成了更明确的出入参结构。

当前 `/user/info` 只依赖当前安全上下文中的登录用户信息，不再支持旧版 `?token=` 查询参数。

### 2. 前端请求头统一

前端请求拦截器已统一改为：

```http
Authorization: Bearer <token>
```

这一轮之后，旧版 `X-Token` 不再作为正式登录态传递方案保留。

### 3. 参数校验与统一异常返回

本轮引入了 `spring-boot-starter-validation`，并新增全局异常处理器，统一把常见参数校验异常转换为项目现有的 `Result` 返回结构。

例如：

- 用户名为空
- 密码为空
- 请求参数类型错误
- 缺少必须参数

这类问题现在会直接返回中文错误信息，而不是让控制器里到处手动判断。

### 4. 用户列表返回结构收口

`/user/list` 现在返回统一的表格数据结构：

- `total`
- `rows`

这样比直接返回 `Map` 更明确，也更方便后续继续做 DTO / VO 收口。

### 5. 开发环境缓存回退到内存

在联调过程中，`/user/info` 会走用户角色与菜单查询，而菜单查询原本挂着 `@Cacheable`。这条链路在测试环境里使用的是 mock / 内存缓存，但开发环境默认连 Redis，一旦本地 Redis 不可用或序列化出现问题，就会被全局异常处理器包装成“系统异常，请稍后重试”。

这一轮后，开发环境默认改成内存缓存，生产环境继续保留 Redis 缓存。这样可以避免本地联调被缓存基础设施阻塞，同时不影响后续生产部署的缓存方案。

## 本轮验证

本轮已在 JDK 21 下执行：

```powershell
./mvnw test
```

测试结果：9 个测试全部通过。

新增或调整的验证重点包括：

- 未登录访问受保护接口会被拦截
- 登录缺少用户名时返回参数校验错误
- `Authorization: Bearer` 可以正常获取当前用户信息
- `Authorization` 触发的跨域预检请求可以正常通过
- 旧版 `X-Token` 不再作为正式认证头使用

## 本轮刻意未做的内容

为了控制风险，这一轮没有把所有控制器都一口气改成 DTO / VO，也没有全面重写前端页面。

目前仍然保留的旧风格点包括：

- 新增用户、修改用户接口仍直接接收 `User` 实体
- 业务异常还没有统一抽成独立异常类型
- 注销接口仍保留原有空实现，后续在令牌失效策略阶段再继续处理

## 下一步建议

下一轮可以继续沿着下面的方向推进：

1. 继续把用户管理相关接口的出入参收口为 DTO / VO
2. 开始引入 Flyway 和数据库版本化治理
3. 补一轮浏览器联调验证清单，确认前端在 Bearer 方案下的实际操作链路
